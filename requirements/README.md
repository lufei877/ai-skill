# 可复用需求库

这里存需求，不存实现代码：记录要解决的问题、所有者已确认的行为、可测试的验收标准、已知的坑和参考链接。新项目可以说「用需求库里的 X」，按卡生成测试，再写实现。

## 卡片索引

| 卡片 | 覆盖范围 | 状态 |
| --- | --- | --- |
| [需求卡模板](_template.md) | 八个必需章节、证据边界与待确认事项 | 模板；不是已确认需求 |

当前尚无中央需求卡，只提供模板与校验；不能把模板当成已确认需求。

## 目录与命名

- `README.md`：卡片、覆盖范围、状态三列索引。
- `_template.md`：新卡起点，不参与需求匹配。
- `<kebab-case>.md`：每张卡一个英文小写文件名，用连字符分词，例如 `license-login-and-terms-consent.md`；标题使用便于用户检索的中文卡名。
- 新卡保留模板的全部八个二级章节，并在索引登记；没有证据的内容放入「待确认」，不能填成已确认行为。

## 复用约定

- 验收标准按一条一个可独立测试的结果编写。
- 验收标准只列已有依据的行为；需要 owner 决定的事项统一放在卡片末尾的「待确认」项中。
- 「待确认」不是默认值；业务决策未补齐前，不得用来源项目的取值代替新项目的决定。
- 参考链接指向来源项目的实现与测试；测试通过只证明仓库测试行为，不代表其他平台或生产环境已验证。

中央卡引用实现和测试时应固定来源提交，便于复查当时证据；其他来源项目适用相同的证据边界。

## 按卡名复用

1. 听到「需求库」或「用需求库里的 X」（例如「用需求库里的卡密登录」），先读本索引，按卡片中文名称或英文文件名匹配，再读匹配卡全文。
2. 多张匹配时列出候选请用户选择；未匹配时明确说明卡片尚未入库，不自行创建已确认行为，也不把只读来源卡冒充中央卡。当前「卡密登录」属于尚未入库的情况。
3. 逐项替换「与项目无关化」中的来源身份、平台与实现约束；需要所有者决定的事项列为待确认，决定前不实现依赖它的行为。
4. 仅依据已有证据且适用于目标项目的验收标准生成测试，先验证测试能检出缺失行为，再完成实现；运行目标项目测试并说明未验证的平台和生产范围。

## 适合与不适合做卡

适合：有确认记录和可测试行为、可以剥离项目身份与参数的卡密登录授权、条款确认、后台队列、长任务进度、独立 Chrome/CDP、账号隔离、日志与崩溃诊断、打包与自动更新。

不适合：选品口径、ROI 等具体业务规则；至多标「仅参考」，不得转成通用验收或新项目默认值。没有确认依据的设想不能进入「已确认的行为」或验收标准。

卡内禁止凭据与真实数据，包括密码、Cookie、token、密钥、真实账号和客户数据；参考链接也不得携带这些内容。测试模板使用虚构角色和脱敏场景描述，不复制业务代码、真实请求或日志。

## 校验

在仓库根目录运行：

```sh
python -X utf8 scripts/validate_requirements.py
python -X utf8 -m unittest discover -s tests -p 'test_requirements.py' -v
```

校验覆盖 `requirements/*.md`：README 仅扫描疑似凭据，模板与需求卡还检查必需章节、固定声明和命名；索引与路由契约由测试覆盖。疑似凭据扫描只检查常见赋值样式及私钥头，不代替人工检查真实账号、客户数据或隐藏在链接中的秘密。报错只输出文件名、行号和原因，不回显命中值。
