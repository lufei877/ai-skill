# 按症状选取诊断方法

这些是候选路径，不是已经确认的根因。先用现场证据选择相关小节。

## 以前正常，更新后失败

- 固定最后正常与当前异常的版本、输入和环境；“大概上周”只是定位线索。
- 差异较小时先看可疑路径的版本差异。只有差异难以收敛且有可重复的通过/失败命令时再二分；无法构建或依赖变化的版本记为不可测试，不误标为故障。
- 二分在隔离 checkout/worktree 内进行，保护未提交文件。检查命中的变更及依赖环境，不能只凭某个提交处于边界就断言具体根因。结束后恢复二分状态，按工具约定清理本次拥有的隔离目录。

## 代码改了，结果不变

- 追踪“权威源 → 编译/生成 → 包 → 安装位置 → 当前进程 → 缓存/持久结果”，核实实际读取路径与版本。
- 生成器是否监听了此源文件，安装入口是否转交给旧进程，PATH 或包装脚本是否运行了另一个版本？检查真实入口，不只从源码目录直接调用。
- 在清缓存或重启前保存能解释问题的状态。只有确认过期且可安全重建才处理对应缓存；不要广泛清空用户数据。修复缓存结构时评估存量数据与失效策略。
- 日志指向已删除的临时目录时先核实路径、归属和调用进程，不将机器上的一次临时目录名写进永久规则。

## 队列、异步、偶发卡死

- 逐段核对请求、入队、领取、持久化、回传和 UI 刷新，使用项目已有 service/API 或授权的只读诊断路径；界面显示“运行中”不能证明 worker 已领取任务。
- 围绕可证伪假设记录事件标识、单调时间/顺序号、线程或任务标识、状态前后值及错误码，不记录凭据、个人资料或完整请求体。
- 确认回调相对取消、销毁、模式切换、重试的时序。日志一加就不再复现，也可能是调度时序变化的证据。
- 桌面卡死先记录准确操作、冷热启动、CPU/内存及可用的线程栈/性能采样，区分主线程等待、忙循环、同步 IO 和事件积压；不要靠调大超时掩盖原因。
- 子进程只在大输出时挂起，检查父进程是否等待退出却未同时消费 stdout/stderr。用超过管道缓冲规模的隔离输入验证，不仅测几行输出。
- 临时日志收尾时移除；必要长期诊断使用项目已有调试开关。未知工具或现场采样能力不可用时说明缺口，不冒充已运行。

## 换入口或环境才失败

- 对照用户实际使用的入口：快捷方式、文件关联、拖放、深链、命令包装器、CI 或计划任务。冷热启动和已有状态可能不同。
- 比较 cwd、可执行路径、版本、区域设置、时区、权限与输入；敏感环境变量只检查是否存在，不回显值。
- 路径操作在写入/删除前核对最终规范路径及符号链接目标。比较预览、dry-run 与执行器的目标集合是否来自同一判定，失败后有没有准确记录已完成和未完成项。
- 非交互环境卡住时检查 stdin、TTY 和隐式认证提示；使用隔离替身验证提示路径，避免用真实凭据或系统状态复现。

## UI 渲染、输入法与 Unicode

- 确认实际渲染的组件实例、视口及状态，对照正常参考；确定性布局问题检查层叠、几何和资源，时序问题检查生命周期，不把功能回归归为审美偏好。
- 输入法提交异常时记录实际 composition/key 事件顺序，验证“确认候选只提交文字，之后主动 Enter 才执行动作”；不能假设所有宿主事件顺序相同。
- 区分字节、UTF-16 单元、码点和字素簇；光标偏移要符合接收 API 的单位，可见字符截断则要考虑组合字符和 emoji。不要机械替换所有字符串长度计算。
- 编码问题从源字节到子进程管道、解码和显示逐层核对，不以屏幕乱码断言文件已损坏。

## 性能或资源增长

保持输入规模、冷热缓存和运行方式可比，记录基线、测量方法和修复后结果。启动慢、主线程卡顿、后台队列慢需要不同指标；采样中的预热/初始零值先核实工具语义。没有前后数据就不写“明显提升”。
