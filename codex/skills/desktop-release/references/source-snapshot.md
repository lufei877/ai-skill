# 源码快照与并行会话

本文件规定输入一致性，不提供已验证的跨项目快照工具。接入时优先复用项目现有机制；新增脚本需要按下列竞态场景测试。

## 发布纳入清单

每项记录：改动说明、来源目录/分支或会话引用、精确提交或文件、是否集成、本次预期行为、对应验收证据。只记录完成当前任务需要的信息，不采集私人会话全文。

“用户要当前修改”不等于只要 HEAD，也不等于要所有分支。检查工作区差异、未跟踪文件、分支/worktree 和已有交付记录。未集成且用户要求纳入的改动阻止本次发布；明确在范围外的进行中工作不阻止其他改动交付。

## 同目录多会话

1. 识别编辑器自动保存、其他 AI 会话、watch 构建等写入来源。启动新目录构建不能自动解决“源目录仍在变化”。
2. 已存在包含所需改动的不可变提交时，直接从该提交建立隔离检出，无需暂停无关开发。
3. 必须捕获未提交改动时，先达成所有相关写入方可实际遵守的短暂停止写入窗口，或使用能提供一致时间点语义的文件系统快照。仅建立打包锁、看到一次 clean 状态或复制前后哈希相等，均不足以证明多文件事务一致。
4. 在稳定窗口中按明确输入清单复制到本次隔离目录，验证文件列表、内容哈希、缺失/新增/删除情况。核对 staged 与 unstaged 的最终工作树内容，纳入需要的未跟踪资源；忽略规则可能漏掉必要模型或生成输入，须单独声明。
5. 快照完成并核对后解除写入窗口。保持快照输入不变，构建输出独立；若项目必须生成源内文件，在本次构建副本生成并记录，不回写共享开发目录。
6. 无法确认写入窗口或可靠快照时，只暂停依赖该快照的动作，给出具体原因和最小所需动作；不能凭等待时间推断其他会话已停止。

不得在用户共享工作区运行破坏性清理、重置、批量 stash、自动提交全部文件或切换分支来制造“干净”。要清理本次隔离目录时验证解析后的绝对路径，避免穿过链接影响其他目录。快照工具须处理或拒绝指向快照外部的 symlink/junction，不能把共享源码通过链接重新引入构建。

## 独立 worktree／分支

1. 精确记录被选中的各分支提交，核实未提交改动是否仍在对应 worktree；创建 worktree 默认不会携带它们。
2. 在独立集成目录合并任务范围内的提交，保留原会话工作区。不要全量扫描并自动合并所有分支。冲突含义或功能取舍不明确时补问，不能选择一侧静默丢弃改动。
3. 验证组合后的业务行为；各分支单独测试通过不证明集成版本通过。记录集成提交与来源提交映射，再开始构建。
4. Git 子模块固定到具体提交；LFS 和外部资源要取得实际内容，不能把指针文件当模型或资源。网络下载的构建输入需要版本/校验值，避免同一提交随时间获得不同内容。

## 无 Git 项目

可以使用稳定窗口内的显式文件快照及内容清单，不强制初始化仓库。本次运行记录 `git_commit: not_applicable`、来源目录标识和快照 SHA-256；不能伪造提交或只用文件修改时间作为版本身份。

## 运行隔离与后续改动

- 每次运行有独立源码快照、构建输出、日志和候选包目录；避免共享 `latest.exe` 作为验证目标。
- 包级并发锁只保护使用它的打包任务，不能阻止其他编辑器写源码。使用锁时记录拥有者和运行身份；不能仅按文件时间删除“过期”锁。
- 两个快照可以各自构建；发布到同一渠道需串行化并校验预期版本，防止较旧构建晚完成而覆盖新发布。正在修改共享发布状态的任务不得被盲目取消。
- 快照建立后出现新修改，报告“本包截至快照 X”；用户要求包含新修改时产生新运行。验收失败需要修代码时，也不得继续复用原包的验收结论。
