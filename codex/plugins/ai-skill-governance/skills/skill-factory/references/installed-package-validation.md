# Skill / 插件安装验收

仅在分发、安装、清单或随包资源变化时读取，不为普通文字修改追加全套安装流程。

1. **确认交付路径。** 找到用户实际获得的包、marketplace 条目、插件源或安装器版本。中央源码、本地生成副本、全局缓存与项目安装可以是不同版本。
2. **检查本次包内容。** 按项目生成方式构建或检查实际产物；核对 SKILL.md、引用资料、脚本、许可和必要清单齐全。相对路径从安装后的包位置解析，不依赖作者工作目录。按需检查执行位、解释器、PATH 包装器和平台依赖。
3. **选择适用的隔离验证。** 本地接入可部署到临时项目并校验引用和包契约；要求真实插件安装时，使用宿主支持的隔离配置/缓存安装本次包，确认能被发现，并通过最小入口核对资源可用性。不要为了冒烟覆盖用户现有安装，也不要绕过稳定发布或项目同步门禁。
4. **检查不该分发的内容。** 核对 `__pycache__`、`*.pyc`、测试缓存、本地日志、凭据或私有现场文件；项目明确需要的样例和资产按清单保留，不把所有图片或数据文件一概删除。只检查当前包，不借机清理宿主缓存。
5. **按实际证据交付。** 分别记录包内容、隔离文件部署、宿主安装/发现、最小调用、模型行为。宿主工具、网络或权限不足时指出缺失的层次；清单可解析、文件能复制或源码测试通过都不能证明宿主已经加载。

验证记录包括产物/源码身份、命令和退出结果、目标路径、实际检查项及未覆盖事实。没有可执行脚本的纯指引包，可验证安装发现和引用可达性；不能用任意无关脚本冒充该 Skill 执行成功。
