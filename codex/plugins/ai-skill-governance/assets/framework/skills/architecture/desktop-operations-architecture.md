# Windows 桌面运营软件架构边界

## 什么时候读

涉及 Windows 桌面 UI、平台自动化、耗时任务、表格异步回填、应用数据路径或迁移时加载。

## 通用边界

1. UI 线程或 Renderer 只负责显示、参数收集、轻量映射和状态订阅。
2. 业务逻辑进入 service，持久化进入 repository，平台细节进入 adapter；UI 不跨层访问数据库或平台实现。
3. 网络、浏览器控制、文件扫描、批量计算和下载必须进入后台任务，并在启动后立即提供可见状态。
4. 异步结果按稳定业务 ID 回填，不按当前行号、当前页数组或控件对象定位。
5. 长任务持久化状态、幂等键、时间戳、错误与来源；重启后恢复，或明确标记中断。
6. 页面展示状态与“全部数据”聚合分离；全量操作独立分页并按稳定 ID 去重。
7. 应用路径由中央路径服务提供。迁移必须验证空/非空目标、锁文件、中文路径、源保留和重启恢复。
8. 凭据只在受信进程和安全存储中使用；日志脱敏，高风险平台写入需要明确授权、幂等保护和回读验证。
9. 外部操作使用超时和按用户动作计算的总重试预算，避免并行分支叠加重试形成请求风暴。
10. 面向用户的进度日志与技术诊断分层；任何失败都必须留下可定位的结构化证据。

## 验收

- UI 在任务执行中仍可导航、筛选和继续提交。
- 排序、过滤、分页、重绘和重启后，状态与结果仍关联正确业务对象。
- 取消和失败不会被标记为成功，也不会污染后续幂等判断。
- 迁移失败可恢复，且不会覆盖非空目标或删除唯一源数据。
