# 测试规范

## 什么时候读
编写测试、修复 bug（应先写复现测试）、重构（确保测试全绿）时加载。

## 规则
1. 修 bug 先写复现测试，再修复，再验证测试通过（Karpathy 原则四）
2. 测试名说清楚：测什么 + 什么条件 + 期望什么结果
3. 一个测试只验证一个行为
4. 不 mock 你不拥有的东西（第三方 API 用 fixture/stub）
5. 测试数据自包含，不依赖外部状态或执行顺序
6. 关键路径必须有测试，边缘场景按风险优先级覆盖
7. 低影响文案、静态样式等改动选择合适的检查，不为形式新增镜像实现的测试；必要检查通过后只因新改动、失败或未解决疑点扩大验证
8. 非平凡行为变化至少留下一个可运行验证；可使用测试、构建、类型检查、命令回放或可重复的运行检查，按风险和项目现有工具选择
9. “代码少”或“只有一行”不能单独证明无需验证；涉及分支、输入边界、状态、IO、并发、公共契约、安全或数据完整性时，验证对应行为
10. 修 bug 写的复现测试保留为回归测试，纳入项目常规测试命令；测试名或注释写明对应的问题编号或现象。不得删除、跳过或放宽已有回归测试来让改动变绿；需求确实改变了该行为时，更新测试并在交付中说明原因
11. 回归测试按执行成本分快、慢两档，判定与运行时机见下节；各档命令写进项目自己维护的说明（如 `.ai-skill/project/context.md`；`detected.md` 每次接入都会重新生成，不要写在那里）。新回归测试默认进快速档，归入慢速档须注明原因；项目已有的完整档、冒烟档作为慢速档的子集保留
12. 有测试的项目，合并前在本地至少运行快速档。检查没有运行、被跳过或无法运行，都不算通过
13. 定期清理测试，但不静默删除：功能删除时，同一变更删除仅服务于该功能的测试；同一逻辑且条件、断言和覆盖等价的重复测试才合并，保留不同边界与故障场景。每月由 agent 整理带依据的清单，列出测试位置、对应行为、删除或合并理由、保留覆盖与验证结果，由人审核后执行；未获审核不得批量删改
14. 不稳定测试（flaky）立即隔离并修复，处置与恢复标准见下节；偶发失败会削弱整套测试的可信度，不能以“重跑就好”结案
15. 测试数量增长本身不是问题，不设数量上限，也不因数量多就删测试。持续管住执行速度、清理和稳定性；耗时增长时先定位瓶颈、优化或分档，按第 13 条的覆盖依据决定合并或删除

## 回归测试分档

| 档位 | 判定标准 | 运行时机 |
| --- | --- | --- |
| 快速档 | 纯逻辑、模拟数据或 fixture，不依赖外部进程、网络服务或真实环境；整档控制在几分钟内 | 每次改动和每个 PR 都跑 |
| 慢速档 | 依赖外部进程或真实环境（如隔离 Electron、启动程序走关键链路的冒烟），或耗时超出快速档预算 | 提交 PR 和发版前都跑；原有合并前或每日运行的安排继续保留 |

各项目记录实测耗时、快速档具体预算与慢档环境前提；根据耗时和依赖共同分档，不能仅因单次运行很快就将真实环境测试归入快档。此处仅定义原则，不统一项目命令或框架；第 7 条的低影响改动验证范围仍适用，分档不构成机械新增测试的要求。

## 不稳定测试的处置

- 同一代码、输入和预期环境下时过时不过，先保留首次失败、环境和复现条件，排查产品故障与测试本身的时序、共享状态或资源泄漏，不能先归咎于测试。
- 确认为 flaky 后立即移入显式隔离集合，记录关联问题、责任人、修复期限、失败证据与受影响覆盖；隔离项单独报告并继续诊断，不得静默跳过或计作通过。若缺少关键覆盖，必须披露验收缺口，不能以其余测试全绿宣称完整验收。
- 禁止把重跑后的成功覆盖首次失败，禁止靠增加重试次数、跳过测试或放宽断言变绿；诊断性重复运行须保留每轮结果。
- 修复根因后，在原失败条件下重复验证稳定且原行为断言通过，再移回原档；交付记录修复依据与恢复验证结果。

## 正例
```python
def test_calculate_discount_returns_zero_for_negative_amount():
    assert calculate_discount(-100, 10) == 0

def test_login_fails_with_wrong_password():
    result = auth_service.login("user@test.com", "wrong-pass")
    assert result.success is False
    assert "invalid" in result.message.lower()
```

    assert func(1) == 2  # 没有上下文

## 输出契约

报告覆盖的行为、执行命令、实际结果与必要的未验证项；不以测试数量替代有效覆盖。
