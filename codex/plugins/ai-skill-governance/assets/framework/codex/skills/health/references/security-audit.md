# 软件安全防御检查

按项目形态选择适用项，不把所有软件套成同一种服务器。每项沿“输入/攻击者能力 → 可达路径 → 信任边界 → 现有防护 → 敏感操作/影响”复核；缺失环节先列待核实。已有正确防护、开发专用且不可达的代码、参数化调用等反证应纳入判断。

| 维度 | 重点核对 | 足以支持发现的证据方向 |
| --- | --- | --- |
| 认证、授权与资源归属 | 登录/会话生命周期、后台接口、角色/租户/对象归属、默认拒绝、凭证撤销 | 普通身份能走到不属于自己的资源；不能只因路由没有装饰器断言未鉴权，先追中间件与 service |
| 输入与执行 | SQL/命令/模板注入、不可信反序列化、动态执行、HTML 注入、上传与导入 | 不可信输入经何种处理进入危险解释器；核对参数化、编码/转义、允许列表及上下文 |
| 文件和归档 | 路径穿越、绝对路径、链接/重解析点、解压越界、覆写、临时文件权限、删除范围 | 真实可控路径如何越过预期目录，或影响其他数据；验证平台路径规则与规范化发生时机 |
| 网络与浏览器 | SSRF、重定向/DNS 与地址限制、CORS/CSRF、Cookie、WS origin/身份、TLS 验证、请求体与并发限额 | 已登录浏览器或远程调用者的现实能力；不能仅因 CORS 宽松断言认证绕过，也不能把 loopback 当作完整访问控制 |
| 秘密与隐私 | 密钥来源/存储、日志脱敏、错误响应、导出与遥测、缓存/备份权限 | 具体秘密类型与暴露位置及可读主体；只记录脱敏位置，勿复述秘密值；历史和运行产物未检查则注明 |
| 桌面与本地权限 | Electron renderer/preload/main 边界、contextIsolation/sandbox/nodeIntegration、IPC sender/参数校验、导航/新窗口、外部 URL、Python worker/本地 API | 远程或不可信页面能否调用高权限能力；先核对加载内容和桥接接口，单个配置开关不足以证明 RCE |
| 状态和滥用防御 | 并发更新、幂等性、重放、队列限额、超时、资源清理、审计记录 | 可重复触发导致越权副作用、资源耗尽或状态不一致；区分一般可靠性问题与可利用安全影响 |
| 依赖与供应链 | 锁定版本、间接依赖、来源、安装脚本、构建权限、更新签名/校验、CI 密钥与外部输入 | CVE 必须对应实际解析版本、公告日期/来源及适用条件；工具/网络不可用时标未核查，不凭包名宣称有漏洞 |
| 部署与防护可观测性 | 监听地址、管理/调试端点、反向代理、生产默认值、权限隔离、拒绝路径日志、恢复/回滚 | 当前发布路径与配置确实会暴露能力或导致防护失效；本地默认值不是生产实况，未取得部署证据应分开写 |

验证优先使用现有测试环境、临时数据、最小离线 fixture 与已有安全工具。体检不隐式授权真实凭据使用、第三方探测、生产攻击、破坏性 fuzz 或业务数据修改。若需要这些才能确认，给出具体待核实项；不要发起无关审批。

修法应落在真实信任边界：例如统一资源归属检查、使用现有参数化接口、限制可接受路径、收窄 IPC 能力、恢复证书校验。复用项目的认证/验证/配置体系，避免为每个命中添加零散正则或盲目升级全部依赖。
