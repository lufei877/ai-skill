# Health 证据复核

本页只解释 Agent 线与 `collect_health.py`；软件安全和可维护性由相应软件参考负责。只读与当前发现相关的小节，采集器提供事实和线索，不判定整个环境是否通过。

## 指令入口与生成归属

- 摘要只读列出的根入口和用户入口，不代表运行时实际加载链。按工作目录及平台约定补查父目录、子目录规则、导入文件、覆盖配置；存在 `AGENTS.override.md` 时注意它可能改变同目录入口选择。
- `agents_reference=explicit_import_signal` 只识别代码围栏外的独立 `@AGENTS.md`/`@./AGENTS.md`，表示源码中有导入信号，不能证明运行时加载。其他自然语言委托需人工读上下文；“Codex 读取 AGENTS.md”只是一句介绍。
- `managed_block=present` 表示 ai-skill 标记恰好各一处且顺序正确，不代表内容最新或生成器安全。检查根规则、项目画像、`scripts/` 中的写入者及调用方，确认谁拥有整个文件、谁只拥有标记段。发现整文件重写会丢失另一套受管段时，用隔离 fixture 复现，不在被审项目运行生成器。
- 多份入口在引用同一事实源或由同一生成器维护时，不应仅因内容重复判为漂移。版本描述需与当前解释器、锁文件或构建选择对照；本机事实不能推广为所有部署机器事实。
- `bytes` 是单文件 UTF-8 字节数（含 BOM），不是 Token、总注入上下文或成本。根文件未超过预算不能证明父级、嵌套、Skill 和运行时说明总量未超标。

## Codex / Claude 配置

- TOML 用标准解析器读取，不能用正则解析表头。Windows 路径比较规范化斜杠、大小写与 `.`/`..`；POSIX 保留大小写意义。
- `project_trust=trusted` 只证明有精确路径条目；`no_exact_entry` 不证明项目未受信任，可能受父路径、配置根或运行时策略影响；`conflicting_entries` 才需要复核重复规范路径的矛盾配置。先确认当前运行时选用哪个配置根。
- 配置文件分别列出，不自动合并 profile、父目录和启动参数；Claude 的本地覆盖也单列。`invalid`/`unreadable`/`too_large` 表示该文件未完成检查。解析错误仅输出错误类型，避免原文错误中夹带秘密。
- Claude 的 MCP 声明从项目 `.mcp.json` 和用户 `~/.claude.json` 读取；用户文件中的项目专属项只匹配当前项目，标为 `project`，不输出其他项目内容。放在 `settings.json` / `settings.local.json` 的 `mcpServers` 标为 `misplaced_mcp_servers`，不当成已配置服务器；这些 settings 文件用于 Hook、权限等设置。插件提供的 MCP 另需启用证据。
- `approval_policy`、`sandbox_mode` 和 allow/ask/deny 数量是当前文件中的声明。用户选择无确认或宽权限并不自动构成健康故障，也不应要求添加通用 deny 模板。只有具体行为与用户约束、信任边界相冲突且有证据时才报告问题。
- Hook 数量不是 Hook 成功回执；读取相关事件、命令、实际触发条件与日志再判断。引用外部脚本时检查来源和固定版本，但不启动它们。

## MCP 和当前会话运行状态

| 静态状态 | 可以得出的结论 |
| --- | --- |
| `disabled` | 文件中有禁用声明，不能算启动失败 |
| `configured` + `missing` | 配置中的绝对可执行路径在本机不是文件；还需确认此配置是否实际生效 |
| `found` | 文件存在，未确认权限、参数、依赖或握手成功 |
| `found_on_collector_path` / `not_on_collector_path` | 仅核对采集进程 PATH；GUI/远程环境可能不同 |
| `relative_unverified` | 相对路径或其他平台绝对路径无法按当前运行目录可靠解释 |
| `network_path_unverified` | UNC/网络路径声明，采集器不探测共享服务器上的程序 |
| `remote` | 有远程地址声明，未发网络请求 |
| `runtime=unverified` | 没有本会话实际工具回执 |

最小探测优先使用已连接工具的无业务写入接口；没有合适接口就保留未知。探测报错应记录工具真实返回，不将请求里自写的 `connected` 文本当作证明。运行时缓存或临时目录故障必须从日志确认确切位置；不要猜测并批量清理临时目录，也不要把某一次缺失目录的路径固化为规则。

## Skill 候选清单

- 按输出的每个 root 递归扫描，跳过输出中的缓存/依赖目录，每个 root 默认最多 4000 个目录，单文件最多 2 MiB。遇到上限、读错或不支持的 name 格式报告 `partial`；不存在的候选根不是故障。
- 支持本库的简单单行 `name` frontmatter；复杂 YAML 标为覆盖缺口，不猜名称。通过真实路径合并同一目录的符号链接或重叠根，避免同一包重复计数。
- 同名不同物理路径只叫“重复候选”，区分内容相同与不同。核对运行时实际启用目录、优先级和来源后再判断冲突。不要把 `.ai-skill/framework`、中央源码、生成副本、插件缓存一股脑加入扫描后宣称重复。
- `activation=unverified`，因此零候选不等于“本会话没有重复 Skill”。若用户需要实际启用范围，以当前会话 Skill 元数据或插件启用回执补充。

## 验证能力与深入体检

- `verifiers.scripts` 是根 `package.json` 中声明的脚本名，命令体不输出。`listing_hint` 只提示名称/参数像帮助或枚举；其余都是 `declared_command`，仍需读实现。不能因为脚本名含 `test` 就判定它执行了断言。
- 深入时针对用户关心的行为跟踪脚本和 CI、已有测试与生成物校验，确认入口是否只打印清单、依赖陈旧缓存或指向失效路径。采集器不运行这些命令；Agent 核实实现与副作用后，按当前授权选择必要的隔离验证。
- 对照重要结果与可执行验证之间的缺口；缺文档、大文件、密集提交或高 TODO 数本身只是线索。仅在有失败、真实交接风险或不可恢复约束时提出必要补充，不开展泛化重构。
- Agent 采集器未实现 Pi 配置、全部插件、秘密扫描或历史会话自动采集；相关请求可按真实平台能力人工补充，并报告具体覆盖，不能冒充已执行上游全部检查。软件安全线也不能用文件清单替代秘密/依赖审查。
