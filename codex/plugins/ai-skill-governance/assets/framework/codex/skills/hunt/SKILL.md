# Hunt

让每次诊断都减少未知：具体症状 → 可证伪假设 → 区分假设的检查 → 最小修复 → 对应验证。根因未查明时保持未知，不用一次成功重启代替解释。

## 工作边界

- 复用用户已给出的目标、现场、正常版本和修复授权。仅要求分析原因时交付诊断；明确要求修复时继续实现和验证，不重复索取计划批准。
- 先查看适用项目指令与工作区状态；没有 Git 时用文件及产物身份建立基线。保留用户未提交改动，不为排查重置、清理或覆盖工作区。
- 排查允许读取源码、日志和已知无业务写入的检查；写诊断代码、执行可能修改数据的复现或外部操作按已有任务授权处理。优先隔离 fixture 和测试数据，避免在真实业务上试错。
- 已有构建失败流程由 `ai-build-fix` 承担；配置与指令体检由 `health` 承担，按需补充诊断，不重复启动另一套完整流程。纯视觉偏好交给可用 UI 能力，有正常参考的渲染回归仍属故障。

## 诊断到验证

1. **固定症状与判定。** 记录预期/实际、触发入口、版本、输入和必要环境差异。用户提供的旧截图、样例或最后正常版本是对照证据；先定义怎样才算恢复。无法稳定复现的偶发问题保留频率和条件，不假装可重复，也不因此停止可用的日志诊断。
2. **追踪实际路径。** 查明触发链和运行身份：使用哪个进程、解释器、安装目录、组件、缓存及生成物。先核对下层输入或状态，再归因于上层显示；当前代码与现场证据优先于旧知识条目。
3. **提出可证伪假设。** 用一句话指向具体函数、状态转换或条件，给出支持证据及能推翻它的结果。逐项核对已知症状；不匹配的现象单列待解释，允许存在多个独立原因，不强行归为一个故障。
4. **做最小区分检查。** 先写或运行最小复现测试；涉及时间、异步或生命周期时，用项目已有工具记录事件顺序和状态变化。证据反驳假设就更新判断，不叠加补丁。重复失败后重新梳理已排除项，只有缺少关键现场、权限或必须由用户决定的取舍才提问，不按尝试次数机械停工。
5. **在授权内修复。** 修改已确认的因果路径。复现测试不适用时，保留等效的命令、输入或 UI 路径，并说明覆盖限制。临时缓解要明确剩余风险和退出条件；根因未明不能宣称根治。
6. **按风险检查相关位置。** 已确认可重复的根因模式时，搜索相关模块和调用方，排除生成物与依赖目录。区分同类缺陷、已有保护和未核实项；必要同类修复沿用当前授权，不扩大为全库重构。只检查了局部就报告局部覆盖。
7. **验证实际结果。** 重跑原复现和受影响检查；UI/桌面故障核查真实运行界面，生成物故障核查产物，性能故障在可比输入下记录前后耗时/资源。编译成功只证明对应层次；当前环境无法验证的事实明确保留，提供具体复核路径。

遇到版本回归、陈旧输出、异步卡死、路径差异或文字输入问题时，按需读取 [references/diagnostic-patterns.md](references/diagnostic-patterns.md)，无需逐项扫描无关模式。

## 输出契约

以用户当前语言交付：

- **结论与证据**：已确认根因，或当前假设和未知；具体文件/函数/状态以及支持和反证。
- **复现与改动**：触发条件、最小复现，已授权且实际完成的修改；诊断任务不把建议写成完成。
- **验证与范围**：运行了什么、实际结果、相关位置检查结论及关键未覆盖项；不要用一个测试通过代表全部症状已恢复。
- **仍未定位时**：已排除的解释、保留的证据、下一项最有区分力的检查及所需现场信息，避免重复尝试同一个失败路径。

本包参考固定版本 Waza Hunt，使用本库持续授权与按风险验证规则。来源、适配边界和许可见 [references/provenance.md](references/provenance.md)。
