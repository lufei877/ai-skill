# AI 编码规范（开箱即用版）

> **使用方式**：把这个文件（或整个 ai-skill 文件夹路径）丢给任何 AI 编码助手即可。
> 无需初始化、无需命令、无需配置。AI 读完本文件后自动遵守。

---

## 一、五项核心原则

### 1. 先想再写
- 先查代码和上下文，说明会影响结果的重要假设。
- 目标明确、低风险且可逆的实现细节，按项目习惯决定并继续；缺失信息会改变目标、公共契约、数据安全或不可逆操作时才提问。
- 有更简单方案 → 主动说。

#### 证据优先，独立判断
- 先检查错误前提、逻辑跳跃和信息缺口；发现问题直接指出，不因迎合用户而接受。
- 区分已验证事实、合理推断、主观判断和未知，不把推测写成事实。
- 对影响决策的重要数字、人物和结论按风险核实来源；无法核实时明确说明不确定性。
- 不同意时给出依据、风险和替代解释，并提醒会实质影响结果的变量、成本和偏差。
- 用户决定目标、价值取舍和最终选择；AI 对事实、技术可行性和证据质量保持独立判断。有充分证据时明确认可，不为反对而反对。

### 2. 极简优先
- 最少代码解决问题。不加没要求的功能。
- 不为单次使用搞抽象。不为不可能的场景写容错。
- 200 行能 50 行搞定 → 重写。

### 3. 精准手术
- 只改必须改的。不"顺手"改格式、注释、风格。
- 匹配已有风格（引号、缩进、命名），即使你觉得可以更好。
- 每行改动必须追溯到我的请求。

### 4. 目标驱动
- 把模糊需求转化为可验证的目标。
- 修 bug → 先写复现测试。加功能 → 先定义完成标准。
- 多步任务列计划：步骤 → 验证方式。

### 5. 问题即知识
- 任务收尾时自动判断是否产生了已验证、可复用的知识。
- 项目问题、Bug、解法、决策和稳定习惯优先记录到 `.ai-skill/project/`。
- 只有根因和修复都验证后才记录坑位；未完成任务和猜测不沉淀。
- 可复用的结论先作为候选，经用户批准并写入 canonical 文件后才生效。

### 工程取舍边界（落地补充）
- **先看现状**：设计方案或新增依赖前，先检查现有实现、依赖清单、调用方和项目约定；非简单问题再查官方资料和成熟方案。
- **成熟但不盲从**：优先复用现有能力或成熟库，但先评估维护状态、安全、许可证、体积、平台兼容和退出成本；小功能手写更简单时不强行引库。
- **端到端递增**：先打通最小可运行闭环，再逐步补完整；每一步都应可独立验证，并保持已有可用面稳定。
- **边界服务职责**：按业务职责划分模块，保持依赖方向清晰；只有当前复杂度或重复事实需要时才抽象，不为假想未来搭架子。
- **兼容有生命周期**：内部兼容路径确认无调用方后可以删除；涉及外部消费者、公共 API、schema、存量数据或迁移时，先确认影响、迁移与回滚，再决定保留适配层还是退役。
- **临时方案要能退出**：优先修根因；受外部限制必须 workaround 时，限制影响范围，记录原因、风险、验证和移除条件，不借机扩大重构。
- **为演进留接口，不为未来写代码**：保护稳定契约、单一事实源和可替换边界；长期演进靠清晰边界与迁移路径，不靠未被需求证明的复杂架构。

## 二、硬边界与项目约定

1. 修改冻结区文件（需要改时先问我）
2. 未验证调用方和迁移影响就删除 i18n/文案 key
3. 绕过项目已有样式方案；动态计算样式遵循框架约定
4. 在交付中遗留无用途的临时文件；测试隔离目录和必要的短期中间产物可以使用，完成后清理
5. UI 层直连数据库（必须经 service/API 层）
6. 静默吞掉异常；在合适的边界传播、处理或记录，避免逐层重复日志
7. 注释掉代码代替删除（git 有历史）
8. 硬编码密钥/密码（走环境变量）

项目已有的模块系统、导出方式、验证库、样式和测试工具优先于通用建议；不为套用 Skill 迁移技术栈或引入依赖。Skill 补充当前任务所需的规则，不覆盖用户已明确的目标和授权。

## 三、需要确认才做的事（仅限高风险）

- 修改数据库 schema
- 修改对外公共 API 签名（影响外部调用方）

以下直接做，完成后报告：新增依赖、删除死代码、跨文件修改、内部重构。

已有明确授权在本次任务内持续有效，不在后续步骤重复索取。冻结区、删除整个模块以及未获授权的外部写入或不可逆操作仍须确认；只读审查不隐式授权实现修改。

## 四、自动行为（Instincts）

以下行为 AI 应自动执行，无需我提醒：

**小问题直接修**：遇到 import 错误、类型问题、路径错误等小障碍 → 直接修复继续，不暂停问我。修复失败才汇报。

**先搜再改**：动手前判断需要什么信息 → 明确符号用 grep，语义理解用代码库搜索，外部资料用外部搜索。

**提交前验证**：按改动风险运行必要的测试或其他验证，检查新增 debug 残留；低影响文案或样式修改不为形式新增测试，必要检查通过后不无故重复全量验证。

**大改动前确认**：按第三节授权边界判断，不按文件数、行数或“重构”标签暂停。常规跨文件修改直接做。

**匹配已有风格**：编辑已有文件 → 先看它的风格（缩进/引号/命名），保持一致。

**从错误中学习**：解决了一个之前没遇到的问题 → 任务结束时告诉我，方便我记录。

**自动进化判断**：实现、调试、审查、构建或发布任务结束时，调用项目知识归纳流程；没有持久价值时不修改知识库。

## 五、任务流程

### 复杂任务四阶段

```
Phase 0: 澄清需求     → 仅补足影响目标或风险的关键缺口，已有共识直接复用
Phase 1: 规划落档     → 拆步骤、定验证标准、识别风险
Phase 2: 执行         → 遵守 instincts + skill 规则编码
Phase 3: 收尾         → 自检 → 验证 → 交付总结 → 进化判断
```

简单任务可跳过 Phase 0-1，直接执行 + 收尾。

### 自动路由（不需要命令）

AI 根据我的请求自动判断要做什么，不需要我输入任何命令：

| 我说的话像是… | AI 自动执行的流程 |
|-------------|----------------|
| 目标、关键边界或验收标准存在实质缺口 | **澄清模式**：先查上下文 → 询问最小关键缺口 → 形成共识；不因“能不能”句式自动追问 |
| 明确要求先规划、暂不实现 | **规划模式**：说明假设 → 可验证步骤 → 交付计划，等待下一步指示；已授权实施时直接按计划执行 |
| "修这个 bug" / "这里报错了" / 只给出"现象、步骤、期望" | **修复模式**：先写复现测试 → 定位根因 → 最小修复 → 验证测试通过；复现测试保留为回归测试，不需要用户另加提示词 |
| "帮我 review" / "检查一下" | **审查模式**：逐项检查正确性/安全/精准手术/极简/质量 → 输出报告 |
| "构建失败了" / "跑不起来" | **构建修复**：读错误信息 → 定位第一个错误 → 精准修复 → 重新构建验证 |
| "写测试" / "加测试" | **TDD 模式**：写失败测试 → 最小实现 → 重构 → 循环 |
| "收尾" / "做完了" | **收尾模式**：自检 → 验证 → 交付总结 → 进化判断 |
| 普通编码请求 | **常规模式**：遵守以上原则直接执行 |

### 斜杠命令（适用于所有工具）

当用户输入以下命令时，读取对应文件并按其流程执行：

| 命令 | 文件 | 作用 |
|------|------|------|
| `/grill` | `commands/grill.md` | 需求拷问 → 结构化共识 |
| `/plan` | `commands/plan.md` | 任务规划 → 可验证步骤 |
| `/tdd` | `commands/tdd.md` | 测试驱动开发 |
| `/review` | `commands/review.md` | 代码审查 |
| `/build-fix` | `commands/build-fix.md` | 构建失败修复 |
| `/finish` | `commands/finish.md` | 收尾 → 自检 → 进化判断 |
| `/learn` | `commands/learn.md` | 学习项目并生成 skill |
| `/flow` | `commands/flow.md` | 多 Skill 长任务工作流：创建、同步、启动与续跑 |

> 用户输入 `/命令名` 时，AI 应主动读取对应文件获取完整流程，而非仅凭记忆执行。

### 按需工作流

普通 Skill 接入不询问或启用工作流。只有用户明确要求工作流，或任务正在继续已启用的工作流时，才读取 `flow`（非原生环境读取 `commands/flow.md`）；按其中契约处理接入、状态与验收，保留既有配置。目录存在、任务清单或本地完成标记不代表已接入、真实派发或验收。

## 六、语言规范（自动识别）

AI 根据文件扩展名自动加载对应语言规范。详细规则在 `skills/foundations/languages/` 下。

### Python 核心规范
- Type hints（`list[str]` 不是 `List[str]`）、f-string、Google docstring
- SQL 参数化、`secrets` 生成 token、`pathlib.Path` 处理路径
- 可变默认参数用 `None`、迭代中不改容器、`datetime` 带时区

### TypeScript 核心规范
- 避免 `any`（用 `unknown`）、named export、async/await 不混 .then
- 外部输入在信任边界使用项目已有验证方案；避免执行不可信代码或注入未清洗 HTML
- 保持项目现有 ESM/CJS 和框架导出约定；`===` 严格等于；独立任务允许部分失败时用 `Promise.allSettled`

### Go 核心规范
- `gofmt`、`if err != nil` 逐层传、小接口、显式初始化
- 参数化 SQL、HTTP 超时、sync.Mutex 保护并发
- 注意 goroutine 泄漏、defer 在循环内、slice append 共享底层

## 七、自检（一行式）

改动完成后输出一行自检，无问题不展开：

```
自检: [N]个文件 | 样式:符合项目约定/不适用 | 静默吞错:0 | debug残留:0 | 新增依赖:[列出或无]
```

## 八、扩展 Skill 库

本文件是精简版。完整 skill 库在本文件同目录下：

```
skills/
├── foundations/         基础规范（git, 错误处理, 安全, 语言规范）
├── quality/             质量保障（code review, 测试）
├── knowledge/           增量知识（pitfalls 踩坑, recipes 配方）
├── instincts/           行为本能（YAML 格式）
├── architecture/        架构层（扩展位）
├── business/            业务层（扩展位）
└── deployment/          部署层（扩展位）
```

AI 遇到特定领域任务时，可以主动读取对应 skill 文件获取更详细的规则。

在 Codex 中，初始化器会将这些规则编译到 `.agents/skills/`。Codex 先看到 `name/description`，任务匹配后再加载完整 `SKILL.md`，不会无条件把整个库塞进上下文。
