# /tdd — 测试驱动开发

## 流程

### 1. 理解需求
- 用户描述要实现的功能或要修复的 bug
- AI 用一句话复述确认理解正确

### 2. 写失败测试（Red）
- 根据需求写测试用例（先不写实现）
- 运行测试 → 确认测试失败（预期的失败）
- 如果测试不能失败，说明测试写得不对

### 3. 最小实现（Green）
- 写最少的代码让测试通过
- 不写超出测试覆盖的功能（极简优先）
- 运行测试 → 确认通过

### 4. 重构（Refactor）
- 在测试保护下重构代码
- 运行测试 → 确认仍然通过
- 检查是否有过度设计

### 5. 循环
- 回到步骤 2，处理下一个用例
- 直到所有需求都有测试覆盖

## 输出契约

提供能先失败后通过的行为测试、最小实现及执行结果，说明重构是否保持行为。
