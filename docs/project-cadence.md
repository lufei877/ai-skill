# 项目进化看板与自适应频率

这是一套中央库内的轻量观察与到期任务接口。用户选择重点项目、基础频率和外部调度器；脚本观察注册项目的内容变化，计算当前频率。脚本不会调用模型、自动生成知识、建立系统任务或自行发布中央规则。

## 打开与选择

在中央 ai-skill 目录运行（Python 3.12 或更新版本，无新增依赖）：

```powershell
python scripts/governance_dashboard.py
```

打开 http://127.0.0.1:8768 。页面展示 `governance/projects.json` 中的项目，点击“检测项目变化”建立基线。勾选“重点项目”，选择每日／每两天／每周和是否自动调频，再保存。

所有项目初始不选中。注册表的 `enabled` 控制是否观察，`sync_approved` 控制中央下发；这两个字段都不代替重点项目选择。状态与选择保存在中央 `governance/cadence.json`，重启看板不会丢失。

## 新项目与漏显示项目怎么接入

三个事实分开显示：**项目侧发现 Skill 框架**、**工作流配置已启用**、**中央看板已登记**。标记存在只证明曾安装或配置，不保证版本最新或工作流已经实际执行。安装器以前只写项目本地文件，不登记中央表，因此会出现“项目已接入、看板却没有”的情况。

1. 打开看板的“接入项目”。已经在“有接入标记、尚未登记”候选里的项目，点击“选择此项目”；不在候选里的，直接粘贴完整项目目录，名称可以留空。
2. 点击“登记到看板”。登记只写中央注册表，不重复安装、不覆盖项目文件；同一路径重复登记会复用原记录，保留已有权限和日程。同名但不同路径会提示改名，不静默合并。
3. 新项目进入下方卡片后，选择是否为重点项目、基础日程和自动调频，保存，再点击“检测项目变化”建立活动基线。登记时的中央分发授权默认关闭，重点日程也默认关闭。
4. 没装过 Skill 的软件项目仍可登记，但卡片显示“未发现安装标记”。在该软件项目的 AI 任务里提出“把当前项目接入 ai-skill，并登记到中央看板”，接入流程会检查并安装项目规则，保留已有政策；首次只选择归档频率，工作流由用户明确需要时另行接入。

也可以在中央库使用明确路径命令，无须手工编辑注册表：

```powershell
python scripts/project_registry.py register --path "/path/to/my-app" --name "my-app"
python scripts/project_registry.py discover
```

候选来源是 `governance/known-projects.json` 中明确列出的绝对路径；本次导入了 Codex 已保存项目的路径快照。页面每次刷新都重新检查这些路径的固定接入标记，不读取未登记项目的源码、会话全文或递归搜索磁盘。不可读路径单独显示，中央库自身及同一路径的重复项排除。

这个清单不是 Codex 项目列表的实时订阅。以后新增或移动了 Codex 项目，可让当前中央库任务“刷新 Codex 已保存项目清单，找出未登记项目”，或直接在看板粘贴新路径。移动已登记项目时应先核对原路径和日程身份，登记入口不会凭同名替换原项目。`known-projects.json` 的格式为 `version: 1`、`source`、`imported_at`、`projects: [{label, path}]`，只能使用用户提供或官方项目列表返回的明确路径。

## 调频依据

| 检测到的情况 | 当前频率的变化 |
| --- | --- |
| 关闭自动调频 | 始终使用用户的基础频率 |
| 48 小时内两个不同日期都有开发文件内容变化 | 调整为每日 |
| 48 小时内只有单日开发变化、当前为每周 | 调整为每两天 |
| 连续完整观察 7 天无开发变化、当前为每日 | 调整为每两天 |
| 连续完整观察 14 天无开发变化 | 调整为每周 |
| 目录不可用、扫描失败或超出扫描上限 | 保持频率，显示原因 |
| 两次成功采样间隔超过 36 小时 | 重新累计连续观察时间，不推断空白期间不活跃 |

升频可立即发生；降频受上一次调频后 48 小时观察期保护。修改基础频率或自动开关会重置当前频率，之后依据新采样再调整。日期边界采用北京时间。

活动图显示成功采样间的内容差异次数，悬停可区分“未采样”和“已采样但无变化”。首次扫描只建立基线；重复扫描不增加活动。内容摘要识别新增、删除和修改，忽略 mtime 单独变化。只观察源码、配置、文档与项目自有知识，排除依赖、构建输出、数据目录和生成的中央框架；不跟随符号链接或目录联接。每个项目限 30,000 个遍历文件、单文件 5MB、累计读取 100MB，超限明确显示检测不完整，不用部分结果降频。

`.ai-skill/project/` 的知识更新单独计数，不能独自升频或重置开发闲置时间，防止定期写整理日志造成自我升频。这里的“开发活动”是采样观察到的源码／配置／普通文档变化，不是打开软件次数、会话数量或生产使用量；两次采样之间发生又撤销的变化也无法检测。

## 用户调度器的接入契约

建议外部触发器**每日运行轻量检测**，再按脚本返回的频率执行完整整理。若触发器本身每周才运行，项目变忙后也要等到下次触发才能被发现。看板中的保存操作不等于外部调度器已经接入。

```powershell
python scripts/project_cadence.py tick
```

返回 JSON 的 `due_projects` 是本次到期项目。只有用户选中、注册启用、最近 36 小时内成功采样、到期且未被其他执行者领取的项目会入列。

对每个到期项目先领取任务（替换 PROJECT_NAME）：

```powershell
python scripts/project_cadence.py claim --project PROJECT_NAME
```

领取返回项目路径、`run_id`、观察摘要和 6 小时租约。重复会话无法领取同一有效租约。租约只是整理任务互斥，不锁住其他开发会话的源码，也不代表已创建 Git 快照；执行者需要核对任务开始时的输入并保存证据。超过租约的旧执行者不能提交结果。崩溃留下的 `cadence.lock` 包含 PID；确认对应进程已结束后才清理该锁，不盲目删除活跃锁。

外部 AI 执行者按四层处理：

1. **项目沉淀**：阅读该项目约定和实际改动，验证根因、修复与稳定决策；必要时更新项目知识或项目自有 Skill。未验证的猜测和进行中的任务不沉淀。
2. **中央候选**：检索已有知识，提炼适用范围、反例与源证据。单项目完整证据可形成 `single-project` 候选，多项目重复提高置信度。
3. **验证提升**：检查冲突，运行核心回归和专项行为场景，比较旧版基线与候选。不能把格式、单元测试或候选数量当成模型行为提升。
4. **稳定分发**：按已有用户授权纳入中央源码；经 `library_release.py` 的行为证据门禁晋升后，才能按注册授权同步。每天整理不意味着每天发布。

在实际检查完成后写一份证据报告，包含输入范围、验证命令与结果、项目知识变更（或无持久价值的结论）、候选链接、未决问题；不要放密钥和会话全文。用领取的 RUN_ID 提交：

```powershell
python scripts/project_cadence.py complete --project PROJECT_NAME --run-id RUN_ID --result no_change --evidence path/to/report.md
```

`completed` 表示完成整理，`no_change` 表示完成检查但没有应沉淀知识，两者都推进下次到期时间；`failed` 保留上次成功时间，6 小时后允许重试。报告归档在中央 `governance/receipts/` 并记录哈希；脚本验证回执绑定及报告非空，不自动认证报告内容的真实性，也不晋升中央候选。工作期间的新采样变化会保留为待检查。

可复用到外部 AI 调度器的任务描述：

> 在中央 ai-skill 目录执行 project_cadence.py tick，仅处理 due_projects。每项先 claim，领取失败则跳过。对领取项目按 docs/project-cadence.md 的四层流程检查，保留原有核心和项目知识；无已验证新知识时不强行改写 Skill。不得把检测或领取冒充完成。为每项真实检查写证据报告并 complete，失败则提交 failed。中央候选遵循已有批准与稳定版本门禁；不修改未选择项目的业务代码，不自行启用工作流模式。

## 验证范围

单元与 HTTP 测试覆盖两天活动升频、十四天降频、采样中断、知识整理反馈循环、过期观察、重复领取、迟到回执、并发设置、文件范围和本地写入保护。浏览器验证和实际首次采样只证明看板及检测可运行；两周真实使用效果、外部 AI 执行质量和真实模型行为提升仍需持续证据。
