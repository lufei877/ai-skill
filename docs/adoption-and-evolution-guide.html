0先理解：全局 vs 项目级的分层架构

ai-skill 的设计核心是两层分离：全局规则库 + 项目级覆盖。理解这个分层，后面所有问题都好办。

全局规则库（你的 ai-skill 仓库）

/path/to/ai-skill\
├── RULES.md           ← 统一入口
├── core/              ← 原则+约束
├── skills/            ← 通用规则
│   └── knowledge/
│       ├── pitfalls.md  ← 全局踩坑
│       └── recipes.md   ← 全局配方
├── commands/          ← 工作流命令
└── evolution/         ← 进化协议

所有项目共享。改这里 = 影响所有项目。

项目级覆盖（每个项目独有）

你的项目/
├── .ai-skill/
│   ├── context.md     ← 项目宪法
│   ├── zones.md       ← 冻结区定义
│   ├── knowledge/
│   │   ├── pitfalls.md  ← 项目专属踩坑
│   │   └── recipes.md   ← 项目专属配方
│   └── skills/        ← 项目专属规则
├── CLAUDE.md          ← Claude Code 入口
├── .cursorrules       ← Cursor 入口
└── AGENTS.md          ← Codex 入口

只属于这个项目。init-project.py 不会动这里。

关键设计：init-project.py 只复制 RULES.md 和生成 IDE 配置文件，永远不会碰 .ai-skill/ 目录。所以你的项目定制（宪法、冻结区、项目知识）在升级时不会被覆盖。

1项目进行到一半，怎么接入 ai-skill？

核心思路：先接规则，再学项目，最后定边界。不需要改任何已有代码。

Step 1: 运行 init（30 秒）

# 在你的项目根目录运行
cd C:\Projects\my-ongoing-project

# 生成所有 IDE 的配置文件
python "/path/to/ai-skill\scripts\init-project.py" --path .

# 或者只生成你用的 IDE
python "/path/to/ai-skill\scripts\init-project.py" --path . --ide cursor

这一步只添加文件，不修改任何已有代码。生成的文件列表见工作流指南。

Step 2: 创建项目宪法（5 分钟）

# 创建项目级 ai-skill 目录
mkdir .ai-skill
mkdir .ai-skill\knowledge

# 复制项目宪法模板
copy "/path/to/ai-skill\core\context-template.md" ".ai-skill\context.md"

# 复制冻结区模板
copy "/path/to/ai-skill\core\zones.md" ".ai-skill\zones.md"

然后打开 .ai-skill/context.md，填写你的项目信息：

## 项目概述
项目名称：my-saas-app
一句话描述：面向中小企业的 SaaS 管理后台
当前阶段：开发中（已完成用户模块，正在做权限系统）

## 技术栈
语言：TypeScript 5.x
前端：React 18 + Ant Design
后端：NestJS + Prisma
数据库：PostgreSQL
...

Step 3: 定义冻结区（3 分钟）

打开 .ai-skill/zones.md，把你项目中不希望 AI 碰的文件列出来：

## 冻结区（AI 绝对不能改）
- src/auth/core.ts            ← 认证核心，手动维护
- prisma/migrations/          ← 已执行的迁移
- .github/workflows/          ← CI/CD 流水线
- package-lock.json           ← 锁文件

## 受控区（AI 可以改，但要先说明）
- prisma/schema.prisma        ← 数据模型，改前要说影响
- src/common/                 ← 公共组件，改前要确认

Step 4: 让 AI 学习项目（可选，2 分钟）

如果项目是 git 仓库，可以跑一次 git 历史分析：

python "/path/to/ai-skill\scripts\learn-from-git.py" --path . --write

或者在 AI 对话中直接说：

# 在 Cursor / Claude Code / 任意 AI 工具里
/learn

AI 会扫描项目结构、采样代码风格、分析 git 历史，然后生成学习报告。

完成后你的项目结构

my-ongoing-project/
├── .ai-skill/               ← 你填写的（项目专属）
│   ├── context.md
│   ├── zones.md
│   ├── knowledge/            ← 后续积累的项目知识
│   └── git-analysis.md       ← learn-from-git 自动生成
├── RULES.md                  ← init 生成的（来自全局库）
├── CLAUDE.md                 ← init 生成的
├── .cursorrules              ← init 生成的
├── AGENTS.md                 ← init 生成的
└── [你的已有代码，完全不受影响]
渐进式采用：你不需要一步到位。先 init + 填宪法就够用了。冻结区、项目 skill、知识库可以随开发逐步完善。

2已有旧版 + 魔改，怎么升级？

假设你的项目之前用的是 ai-skill v1，你做了一些定制（加了项目 skill、改了规则、积累了踩坑记录），现在要升级到新版。

先搞清楚：哪些是"全局"的，哪些是"你的"

文件来自哪里升级时会怎样
RULES.md全局库（init 生成）会被覆盖 → 拿到新规则
.cursorrules全局库（init 生成）会被覆盖 → 拿到新规则
CLAUDE.md全局库（init 生成）会被覆盖 → 拿到新规则
AGENTS.md全局库（init 生成）会被覆盖 → 拿到新规则
.ai-skill/context.md你填的不会被动 → 安全
.ai-skill/zones.md你填的不会被动 → 安全
.ai-skill/knowledge/*你积累的不会被动 → 安全
.ai-skill/skills/*你写的不会被动 → 安全

场景 A：没改过全局规则，只加了项目级定制

最简单。直接重新 init：

# 直接跑，只有 RULES.md 和 IDE 配置会更新
# .ai-skill/ 完全不受影响
python "/path/to/ai-skill\scripts\init-project.py" --path .

完事。你的所有项目定制（宪法、冻结区、知识库、自定义 skill）原封不动。

场景 B：魔改过 RULES.md 或 .cursorrules

如果你直接改了项目里的 RULES.md（比如加了几条项目专属规则），重新 init 会覆盖它们。

升级步骤

1. 备份你的魔改
copy RULES.md RULES.md.mine
2. 执行 init 拿到新版
python "/path/to/ai-skill\scripts\init-project.py" --path .
3. 对比差异，合并你的魔改
# 用任意 diff 工具对比
git diff --no-index RULES.md.mine RULES.md

# 或者让 AI 帮你合并
请帮我把 RULES.md.mine 中我自定义的规则合并到新版 RULES.md 中
4. 清理备份
del RULES.md.mine
更好的做法（推荐）：不要直接改 RULES.md。把项目专属规则放到 .ai-skill/ 下。这样 init 永远安全，升级零冲突。

正确的定制方式：项目级覆盖

把你的魔改内容迁移到正确的位置：

你魔改的内容应该放在哪里怎么迁移
加了项目专属的禁止项 .ai-skill/constraints.md 从 RULES.md 中摘出来，写到项目级文件
加了特定技术栈的规则 .ai-skill/skills/my-rule.md 用 skill 模板创建独立规则文件
修改了某条原则的表述 .ai-skill/context.md 的"关键约定"区 写在宪法里，项目级覆盖全局
加了项目专属的 instinct .ai-skill/instincts/my-instinct.yaml 用 instinct 格式独立保存

迁移完成后，你的 RULES.md 保持和全局库一致，升级永远是一条命令的事。

3其他项目总结的经验，怎么复用到新项目？

这是 ai-skill 的核心价值之一：知识不锁在某个项目里，通用经验向上沉淀到全局库。

知识流向图


项目 A 发现一个坑

        ▼

ai-skill/skills/   项目A/.ai-skill/

自动继承全局知识

操作方法：从项目 A 提炼经验到全局库

方式 1: AI 自动提议（推荐）

在任务结束时（/finish 或 AI 自动进入收尾），AI 会按进化协议判断：

# AI 在 /finish 时的判断逻辑：

这次解决了一个有通用价值的新问题？
  → Yes → "建议记录到全局 pitfalls：PIT-004: ..."
  → No  → 跳过

这次用了一个值得标准化的多步操作？
  → Yes → "建议记录到全局 recipes：RECIPE-004: ..."
  → No  → 跳过

# AI 只提议，你确认后才写入

方式 2: 手动记录

在任何 AI 对话中直接说：

# 记录一个通用踩坑
帮我把这个问题记录到 ai-skill 全局 pitfalls：
Prisma 的 connectOrCreate 在并发时会 race condition，
需要用 $transaction + upsert 代替

# 记录一个通用配方
帮我把这个操作记录到 ai-skill 全局 recipes：
NestJS + Prisma + PostgreSQL 的事务处理标准步骤

AI 会按格式追加到 ai-skill/skills/knowledge/pitfalls.md 或 recipes.md。

方式 3: 运行健康度检查，发现待沉淀的知识

python "/path/to/ai-skill\scripts\sync.py" --health

# 输出示例：
# [HEALTH] 进化健康度报告:
#   踩坑记录: 3 条
#   操作配方: 3 条
#   进化日志: 1 条

新项目怎么自动拿到这些经验？

当你对新项目 B 运行 init-project.py 时，生成的 RULES.md 包含了对全局 skill 库的引用。AI 在需要时会主动读取 ai-skill/skills/knowledge/ 中的全局知识。

具体来说，RULES.md 中的这段话告诉了 AI：

## 八、扩展 Skill 库

本文件是精简版。完整 skill 库在本文件同目录下：
skills/knowledge/pitfalls.md  ← AI 遇到类似问题时会来查
skills/knowledge/recipes.md   ← AI 需要标准步骤时会来查

加上路由规则中的第四级"遇到问题时查阅"，AI 会在遇到相关问题时自动检索全局知识库。

跨项目复用的完整流程

# 项目 A：在一个项目中积累知识
项目 A 开发中
  → 遇到 Prisma 并发 bug，解决了
  → /finish 时 AI 提议记录
  → 你确认 → 写入 ai-skill/skills/knowledge/pitfalls.md

# 项目 B：新项目自动受益
python init-project.py --path 项目B/
  → 项目 B 的 RULES.md 引用了全局 skill 库
  → AI 在项目 B 里遇到 Prisma 并发问题
  → 自动查 pitfalls.md → 找到 PIT-004
  → 直接用正确的方式处理，不再踩坑

# 项目 C：同理，所有新项目自动继承

4进化机制：知识怎么持续增长？

进化的四种方式

进化类型触发条件写入位置示例
踩坑进化 解决了一个之前没记录的问题 pitfalls.md PIT-004: Prisma 并发 race condition
配方进化 完成了一个值得标准化的多步操作 recipes.md RECIPE-004: NestJS 事务处理标准步骤
Skill 进化 某领域已积累 ≥3 条 pitfall/recipe 新建 skill 文件 skills/foundations/prisma.md
反馈进化 用户纠正了 AI 的行为 对应规则文件 "不要自动格式化 SQL 文件" → 加入约束

进化触发时机

/finish 收尾时（主要触发点）
AI 执行完任务后，自动检查是否有值得记录的新知识。这是最常见的进化时机。
Instinct "从错误中学习" 触发
AI 解决了一个之前没遇到的问题时，instinct 会提醒它在任务结束时提议记录。
你主动要求记录
任何时候你都可以说"把这个记录下来"或"这个值得加到 pitfalls"。
定期健康度检查
运行 sync.py --health 查看知识库增长情况，发现空白领域。

进化的安全规则

  1. 只增不改 — 已有记录只能追加，不能修改或删除
  2. AI 提议，人确认 — AI 建议记录什么，但不会自行写入
  3. 通用优先 — 只有跨项目通用的知识才写入全局库
  4. 去重检查 — 追加前检查是否已有类似记录
  5. 质量门槛 — 不记录一次性的、显而易见的问题

从量变到质变：Skill 升级

当某个领域积累了 ≥3 条 pitfall/recipe 时，就值得升级为独立 skill：

# 进化路径示例：

PIT-004: Prisma connectOrCreate 并发问题
PIT-007: Prisma $transaction 嵌套时的死锁
RECIPE-004: NestJS + Prisma 事务标准步骤
RECIPE-008: Prisma migration 安全操作

# 积累 4 条 → AI 提议：
"建议将 Prisma 相关知识升级为独立 skill：
 skills/foundations/prisma.md"

# 你确认后，AI 创建新 skill，把散落的知识整合进去

进化日志

每次进化操作都会记录到 evolution/log.md：

- 来源：项目 A 的支付模块开发
