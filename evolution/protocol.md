# Skill 自我进化协议

> 让 skill 库随使用自动生长。AI 在工作中发现新知识时，按本协议追加。

## 进化触发条件

以下情况触发进化行为：

1. **踩坑进化**：解决了一个之前没有记录的问题，且该问题有通用价值
2. **模式进化**：发现同一类问题反复出现（≥2次），值得提炼为规则
3. **配方进化**：完成了一个多步操作，步骤值得标准化
4. **Skill 进化**：某个领域积累了足够多的 pitfall/recipe，值得升级为独立 skill
5. **用户反馈进化**：用户纠正了 AI 的行为，该反馈值得固化为规则

## 进化动作

### 动作一：记录踩坑
- 目标文件：`skills/knowledge/pitfalls.md`（跨项目）或 `项目/.ai-skill/project/knowledge/pitfalls.md`（项目级）
- 格式：`### PIT-{编号}: {标题}`
- 必填：现象、原因、解决方案、日期
- 约束：先去重；新证据补充现有 active 条目；规则变化时用 `superseded_by` 替代

### 动作二：记录操作配方
- 目标文件：`skills/knowledge/recipes.md`（跨项目）或 `项目/.ai-skill/project/knowledge/recipes.md`（项目级）
- 格式：`### RECIPE-{编号}: {标题}`
- 必填：场景、步骤、注意事项
- 约束：保留一个权威版本；失效流程标记 superseded，不复制近似条目

### 动作三：记录偏好与决策
- 用户明确偏好 → `项目/.ai-skill/project/preferences.md`
- 行为推断偏好 → 至少两个独立任务证据后记录
- 产品/架构决定 → `项目/.ai-skill/project/decisions.md`
- 用户最新明确决定优先，可替代旧决定但必须保留替代关系

### 动作四：创建新 Skill
- 前提：存在重复任务、稳定触发边界与可验收输出，并有证据表明独立 Skill 比普通提示或现有 Skill 更有用；条目数量不作硬门槛
- 动作：从 `skills/_template.md` 创建新 skill 文件
- 位置：对应分类目录下
- 约束：需要用户确认后才写入

### 动作五：记录进化日志
- 目标文件：中央库用 `evolution/log.md`；项目用 `.ai-skill/project/evolution/log.md`
- 每次进化操作都追加一条日志
- 格式见下方

## 进化日志格式

```markdown
### EVO-{编号} | {日期}
- **类型**：pitfall / recipe / new-skill / rule-update
- **来源**：{什么任务/问题触发的}
- **内容**：{简述追加了什么}
- **文件**：{修改了哪个文件}
```

## 进化约束

1. **证据优先**：记录证据类型、验证日期、适用范围和 active/superseded 状态
2. **项目优先**：单项目完整证据先留项目库并可生成中央候选；多个项目重复验证提升置信度，但候选发布仍需用户批准
3. **敏感信息隔离**：不记录密码、Cookie、token、密钥或原始会话全文
4. **质量门槛**：不记录一次性命令、未完成任务、推测根因或显而易见常识
5. **去重与纠错**：更新权威条目，允许显式替代过时规则，不让错误永久累积
6. **Skill 门槛**：新增独立 skill 前告知用户；普通项目知识可按本协议直接更新并在收尾报告
7. **候选**：未经验证的规则先作为候选，经用户批准并进入 canonical 文件后才生效

## 中央迭代防退化

中央更新复用 `core/behavior-contract.json` 的核心底线与 `evals/core-behavior-cases.json` 的行为案例；不再创建另一套常驻原则。

- 保留修改前快照；新增内容检查与已有 Skill 的冲突、重复和适用边界，减少内容也是有效进化。
- 五项原则、授权边界、评测输入与验收条件不能为通过检查而弱化。普通发布可追加案例，不可改写既有核心案例；需要纠正核心契约时单独审查和授权迁移，保留旧版本与说明。
- 结构、词语路由、行为执行、独立评分分别提供证据。缺少行为记录时保持候选，禁止声称效果提升或下发稳定版。
- 多会话操作绑定候选摘要与预期稳定版本；捕获源码前协调相关写入者，运行锁不代表编辑器已停止。
- 被评测否决的改动在 `evolution/log.md` 中记录，写明尝试、失败证据及是否恢复，避免下次重复引入。

## 进化健康度指标

定期（或用户要求时）报告：
- 条目是否包含适用范围、证据、验证日期和有效状态
- 重复、错误归类与已失效条目是否被合并、纠正或显式替代
- 实际复用、复发与纠错证据；无运行记录时标记未知，不以新增数量推算收益
- 是否存在稳定的重复任务值得形成 Skill；空分类不要求补齐
