# 验证证据等级与完成声明

## 什么时候读

涉及完成声明、桌面运行、远程平台、打包产物、真实写入或正式发布时加载。

## 证据类型

1. 静态源码检查
2. 聚焦回归测试
3. 更广自动化测试
4. 类型、语法、格式和源码构建
5. 真实桌面 UI/运行时检查
6. 打包产物检查
7. 真实远程 API 或平台只读检查
8. 真实下载、付费生成或生产数据写入
9. 安装、签名、升级保留和目标机器发布验收

这些编号用于索引，不构成必须逐级完成的流程。源码测试、安装运行和平台写入分别证明不同事实；按交付目标选择适用证据，逐项报告，不能用“最高等级”概括所有维度已通过。

## 声明规则

- 非平凡行为变化至少要有一个与改动对应的可运行验证；验证形式按风险和现有工具选择，不为低影响改动机械增加测试。
- 只跑自动化测试：说“实现完成且自动化测试通过”。
- 检查真实桌面界面后：才说“真实界面已验证”。
- 授权执行并回读真实数据后：才说“真实写入已验证”。
- 安装包及目标机验收完成、项目实际要求的签名和升级验证通过后，才说“满足本次正式发布条件”。首次发布无旧版本时，升级验证记为不适用；项目不要求签名时明确该策略，不虚构签名结果。
- 未执行的等级必须显式说明，不用推测填补。
- 代码行数少、文件数量少或 diff 较短都不是完成证据，也不能替代安全、数据、迁移、公共契约或发布验收所需检查。

## 跨层改动

修改 UI、preload/bridge、主进程、worker、服务或打包配置时，要重启或重建实际受影响层。进程仍存活不代表窗口、路由、资源或新代码已生效。

## 输出契约

逐项对应完成声明与实际证据，列出尚未验证的关键事实；任何一种证据都不自动证明其他维度。
