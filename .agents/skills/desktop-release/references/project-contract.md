# 项目接入与证据

这是接入时要填实的契约说明，不是可直接运行的配置格式，也不要求引入新的 schema 或依赖。优先扩展项目已有发布配置与报告；无对应位置时可采用项目内 `release/contract.md`，运行证据放独立产物目录。

## 最小项目契约

| 项目事实 | 需要记录的内容 |
| --- | --- |
| 软件与目标 | Electron、Python 或组合；目标系统、CPU 架构、安装器类型 |
| 当前工具链 | 包管理器及锁文件、Node/Electron/Python 和打包器版本；实际安装/构建/打包命令及工作目录 |
| 源码边界 | 共享目录或 worktree 模式；集成来源、快照方法、输入清单、显式排除项、外部资源版本 |
| 运行资源 | 各入口、Python 组件、原生库、模型、模板、非敏感配置；开发路径与安装后路径的对应 |
| 身份检查 | 应用与组件的构建编号如何嵌入、安装后如何读取和核对 |
| 验收场景 | 本次改动的预期行为、最小业务链路、测试数据与环境、适用的升级与签名要求 |
| 交付 | 本地候选包目录、报告目录、发布渠道及是否已获授权 |

把查不到但影响正确性的项列为待核实，不能把默认假设写成已验证事实。非敏感构建配置可记录内容或摘要；凭据仅记录来源标识，避免日志或报告泄密。

## 本地与 CI 共用实现

先让项目的单一命令在本地完成最小闭环，再由 CI 调用。沿用现有包管理器与打包工具，不强制命令命名，不预设 `npm run build` 已包含 Python 和安装器。

- CI 固定源码提交、工具链、目标架构和锁定依赖；没有锁文件时先建立适合项目的锁定方案，现有冻结或迁移约定继续适用。
- 质量检查按实际改动与项目约定选择；纯 Python 不需要 TypeScript 检查，本阶段不新增体积门禁。安装后的关键行为验证不能被源码检查替代。
- Windows 原生依赖、Python 打包与安装验收应有对应 Windows 环境；其他目标系统亦需对应证据，不默认 Linux 构建能覆盖所有桌面目标。
- 上传候选包和脱敏日志便于排错，保存期限沿用项目策略；上传 CI artifact 不等于公开发布。
- 配置安装/GUI 测试所需的 runner 能力，远程服务账户和无桌面会话可能无法验证窗口。记录环境限制，不用“CI 绿了”掩盖缺失阶段。
- 发布任务依赖适用验收成功，消费同一产物，不再次构建；为同一渠道设置串行化与版本检查，按已有授权决定是否发布。
- 自托管 runner 的临时目录、端口及用户数据需按运行隔离；结束时只清理该运行拥有的资源。

## 运行证据字段

可以用 Markdown 表格或项目现有 JSON 报告表达以下字段；日期使用带时区的 ISO 时间。

| 字段 | 语义 |
| --- | --- |
| `run_id`, `created_at`, `owner` | 唯一运行及负责人/执行任务；重试必须可区分 |
| `source` | 精确集成提交（适用时）、源码快照指纹、输入清单及外部输入版本 |
| `changes` | 每项改动来源、纳入/排除/未集成状态、预期行为、验收结果 |
| `environment` | 目标 OS/架构、构建环境、工具实际版本、依赖锁摘要、非敏感配置身份 |
| `components` | 各组件构建身份与本次运行映射 |
| `artifact` | 最终文件绝对路径、字节大小、SHA-256、适用签名结果 |
| `checks` | 检查对象、命令/操作、环境、时间、状态、退出码及日志/截图/报告路径 |
| `runtime` | 安装路径、真实进程路径、构建编号、测试账户/隔离环境标识 |
| `delivery` | 是否已交付、交付文件身份与位置；发布单列渠道和可信回执 |

`run_id` 仅用于关联，不能代替内容指纹。源码指纹基于确定顺序的相对路径和文件内容摘要，纳入新增/删除/路径变化；明确大小写、链接和文本换行策略。不要将安装包自身哈希嵌进该安装包。报告中的路径须存在并对应本次运行，缺失日志不能靠描述补成证据。

完成报告同时列出 `built / artifact_checked / installed_verified / delivered / published` 的实际状态。`delivered` 不能暗示 `installed_verified`；用户明确需要未验收候选包时可以交付，但必须显式标注缺失验证。
