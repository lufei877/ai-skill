# /plan — 任务规划

## 流程

### 1. 理解任务
- 复述用户需求
- 列出假设和不确定项（原则一：先想再写）
- 如有多种理解方式，列出选项让用户选

### 2. 拆解步骤
将任务拆为可验证的步骤（原则四：目标驱动）：

```
1. [步骤描述] → 验证方式: [如何确认完成]
2. [步骤描述] → 验证方式: [如何确认完成]
3. [步骤描述] → 验证方式: [如何确认完成]
```

### 3. 风险评估
- 涉及哪些文件（检查冻结区）
- 预计改动范围
- 可能的副作用
- 是否需要用户确认

### 4. 按请求交付或执行
- 用户只要求规划时交付计划，等待下一步指示；已明确授权实施时，不额外索取计划批准
- 按步骤依次执行
- 每步完成后验证

## 输出契约

交付目标、重要假设、可验证步骤和风险；规划请求到计划结束，实施请求按既有授权继续。
